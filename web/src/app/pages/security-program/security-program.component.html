Information security

Documented information security policy and procedures for Health Tracker & PFM (Personal Financial Management). This page describes how we identify, mitigate, and monitor information security risks relevant to operating the service and handling your data.

Policy statement

We maintain documented information security policies and procedures that are operationalized to identify, mitigate, and monitor information security risks relevant to our business and to your use of this application.

The program is owned and updated as the product and integrations evolve. Controls are applied in design, deployment, and day-to-day operations—not only on paper.

Program scope

The security program covers at least:

  • Governance and policy ownership
  • Access control and authentication
  • Secure configuration and hardening
  • Logging, monitoring, and incident handling
  • Change management and deployment control
  • Data protection and secrets management
  • Risk assessment and remediation tracking
  • Privacy notices and recorded acknowledgment paths for sensitive integrations (including financial data via Plaid)

Operational procedures

Identify risks

We use a combination of practices to surface security risks early and on an ongoing basis:

  • Review architecture and data flows when features change (including third-party integrations).
  • Track known issues and remediation in internal change and release processes.
  • Rely on secure defaults (transport security, authentication, authorization, and safe error handling).
  • Align operational evidence with partner and regulatory expectations where applicable.

Mitigate risks

Identified risks are addressed with layered controls, including:

  • Authenticated access to application features and APIs; role-based restrictions for administrative functions.
  • Strong password handling (one-way hashing with per-user salt and server-side secret material).
  • HTTP security headers and TLS for data in transit.
  • Controlled uploads and import paths with size and validation limits.
  • Secrets and environment-specific configuration supplied only through secure deployment channels.
  • Database changes applied through controlled, reviewed migration processes in production.

Monitor and respond

We support ongoing assurance through:

  • Request and error logging with redaction appropriate for authentication and sensitive payloads.
  • Deployment automation and repeatable release processes.
  • Incident handling expectations: report suspected vulnerabilities through private channels; do not post exploit details in public forums.

Responsible disclosure

If you discover a security issue, report it privately to the maintainers through your existing support or security channel. Do not open a public issue with exploit details.
